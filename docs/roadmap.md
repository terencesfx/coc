# 开发路线

## 阶段 0：工程骨架

- 初始化 React + TypeScript 前端；
- 初始化 Go 服务；
- 建立 SQLite 数据库连接、迁移和本地数据目录；
- 配置格式化、静态检查、测试和环境变量样例；
- 建立统一错误格式、日志、请求 ID 和健康检查。

验收：新环境可通过明确命令启动前端和后端，后端自动创建或升级 SQLite 数据库。

## 阶段 1：认证和基础布局

- 管理员初始化及账号管理；
- 登录、退出、修改密码和会话撤销；
- 桌面与移动端基础导航；
- 前端路由、API 客户端和权限守卫。

验收：管理员可创建朋友账号，用户可以登录并修改密码，未登录无法访问业务页面。

## 阶段 2：人物卡当前状态

- CoC 7 版人物卡 schema；
- 人物卡档案列表；
- 创建、原位编辑、自动保存、归档和复制；
- 属性生成和派生值；
- 技能搜索和常用技能；
- 保存状态与并发冲突提示。

验收：一张人物卡能够从创建到日常跑团完整使用，刷新页面不丢数据。

## 阶段 3：历史系统

- 每次逻辑修改生成快照与差异；
- 历史时间线、筛选、版本详情和版本比较；
- 恢复旧版本；
- 自动保存合并策略和并发测试。

验收：能准确还原人物卡任意版本；恢复不破坏原有历史；多人同时编辑不会静默覆盖。

## 阶段 4：团本与权限

- 团本创建和管理；
- 公开/KP 富文本内容块及图片；
- 调查员与 NPC 挂靠；
- NPC 可见性；
- 后端权限矩阵测试。

验收：不同账号和 KP 看到的内容符合权限表，秘密数据不会出现在无权用户的 API 响应中。

## 阶段 5：投骰

- 安全的骰子表达式解析；
- CoC 7 版技能检定、奖励骰和惩罚骰；
- 人物卡快捷投骰；
- 公开、暗骰、测试骰及日志；
- 请求幂等和重投关系。

验收：前端无法指定或篡改结果；重复请求不产生第二个结果；暗骰不会泄漏。

## 阶段 6：通知预留与完整测试

- 通知任务表和后台工作器；
- Disabled/Console 通知实现；
- 消息格式化、重试和投递状态；
- 权限、历史、骰子和关键用户流程的集成测试。

验收：本地不依赖 QQ 也能验证全部通知流程，通知失败不影响投骰。

## 阶段 7：体验与部署

- 邀请朋友试用并调整操作流程；
- 统一最终视觉主题；
- 按部署时 QQ 官方接口实现机器人适配器；
- 数据备份、恢复、HTTPS、限流和运行监控；
- 编写部署与升级说明。

验收：先在测试环境完成整套流程，再启用真实 QQ 群推送并部署正式环境。

## 开发优先原则

1. 数据正确和权限隔离优先于视觉效果；
2. 历史不可丢失，恢复操作不可改写历史；
3. 外部通知不能阻塞核心投骰；
4. 规则逻辑集中在后端并有单元测试；
5. 页面业务状态与视觉组件分离，为最终换肤保留空间。

SQLite 数据库文件和上传资源需要作为一个整体进行定期备份。备份数据库时使用 SQLite 在线备份能力或安全检查点流程，不直接复制正在写入中的多个 WAL 文件。
